NPBデータ更新・完全運用マニュアル (2026年版)

このマニュアルは、シーズン終了後に「最新の成績」をシステムに反映させるための手順書です。
1. 準備フェーズ：環境の生存確認

作業を始める前に、VS Codeの環境が整っているか確認します。

    VS Code を開き、プロジェクトフォルダ (my-baseball-app) を選択。

    仮想環境の起動: ターミナルで以下を確認（左側に (.venv) と出ていればOK）。
    Bash

    # 出ていない場合は起動
    .\.venv\Scripts\activate

    ライブラリの確認: 以下の2つが入っていれば準備完了。

        supabase: DB通信用

        httpx: 通信安定化用（pandasはDLLブロック回避のため不要）

2. 収集フェーズ：スクレイピングの実行

最新シーズンの「生データ」を取得します。

    対象サイト: スポナビ（成績詳細）、NPB公式サイト（選手ID）。

    注意点: * 選手名が「登録名変更」されていないか。

        player_id が必ず含まれているか（これが無いと名寄せに失敗します）。

        守備位置データが「内野手/外野手」等の大まかな区分で取得されているか。

3. 計算・分析フェーズ：main.py の実行

取得した生データをSupabaseに送り、セイバーメトリクス指標を自動算出します。

    main.py の定数確認:

        lg_fip_const = 3.12 (2026年基準定数) が適切か確認。

    不変のロジック: 以下の計算が自動で行われます。

        投手: 投手WAR, FIP, WHIP, K/BB, K/9, BB/9, ランク判定。

        野手: 野手WAR, wOBA, wRC+, OPS, ISOp, ランク判定。

    実行:
    Bash

    python main.py

4. 同期フェーズ：バッチ処理によるDB更新

大量のデータを安全にSupabaseへ流し込みます。

    処理の仕組み: batch_upsert 機能により100件ずつ小分けに送信（タイムアウト防止）。

    名寄せのルール: player_id と 年度 が一致する行を自動で探し出し、最新の分析数値で上書きします。

    成功の証: ターミナルに 【成功】 player_idと年度をキーにした更新が完了しました。 と出れば完了。

5. 検証フェーズ：事実の確認 (SQL)

正しく反映されたか、SupabaseのSQL Editorで「最終検品」を行います。
① 全体の分布確認
SQL

SELECT "年度", "ランク", COUNT(*) 
FROM batting_stats 
WHERE "年度" = 2026 
GROUP BY "年度", "ランク" 
ORDER BY "ランク";

② 特定選手の推移確認 (例: 矢崎投手)
SQL

SELECT "年度", "名前", "投手WAR" 
FROM pitching_stats 
WHERE "player_id" = '71575134' 
ORDER BY "年度" DESC;

💡 トラブルシューティング（転ばぬ先の杖）
起きそうな問題	原因と対策
DLL load failed...	pandas を使おうとしています。標準の csv モジュールを使う「軽量版コード」を使用してください。
重複エラー (Unique constraint)	DB側に古い 名前 基準の制約が残っています。SQLで DROP CONSTRAINT を行い、player_id 基準に更新してください。
KeyboardInterrupt	通信が重くて止まった状態。batch_size を 50 程度に下げて再試行してください。
